### Deviation: the dirty-tree stop condition

Both documents say to stop if `git status --short` prints anything. On the VM it printed
` M backend/mvnw.cmd`, which made `git merge --ff-only` refuse. Findings:

- The change was **line endings only** — 0 content lines differ ignoring EOL — and `git ls-files --eol`
  showed `i/crlf w/crlf` under `.gitattributes` `*.cmd text eol=crlf`: the stored blob at `7e58530` was
  never normalized, so git reports it modified however the file is checked out. `git checkout --` did
  not clear it. Upstream commit `796f71c` ("renormalize mvnw.cmd line endings") fixes exactly this.
- It was resolved by pre-staging the target commit's version of that **one** file
  (`git checkout origin/main -- backend/mvnw.cmd`), after which the fast-forward succeeded and the tree is
  clean at the new HEAD. No other path was touched; the VM's diff was kept off-box before changing anything.
- Consequence for the runbook: any deploy from a checkout older than `796f71c` will meet this gate.
