# S4 — ESPN league import: build plan

**Status:** planned, not started (owner, 2026-10-30). This expands Part B S4 of
`2026-10-28-leagues-trades-plan.md` against the code S1–S3 actually shipped. Owner decisions 1–3
stand: ESPN after Sleeper; private-league cookies stored encrypted **only on opt-in**, with
use-once-and-discard as the default; one copy of a league per member.

## Owner inputs

1. **An ESPN league to verify against.** A public league id is enough for S4a. For S4b, a private
   league whose cookies **you** paste into the local app yourself. Claude does not enter
   credentials. Without one, S4 ships on synthetic fixtures shaped on the defaults and the
   community client, and the real-league gate stays open, as S1's does.
2. **S4b deploy:** generate `LEAGUE_CREDENTIAL_KEY` (32 random bytes, base64) and put it in the
   VM's `.env`. Back it up separately from the database: a lost key means every stored ESPN
   connection must reconnect.
3. **ESPN's request budget.** No rate-limit header exists. The proposal is 120 calls a minute
   shared by all members, well below anything observed. Confirm, or set another.

## Design

### The S1 seams that need widening (each small, each tested)
- **`LeagueProvider`** takes an access argument: `fetch(id, season, access)` and
  `schedule(id, season, weeks, access)`. `LeagueAccess` is a sealed type: `None` or
  `EspnCookies(espnS2, swid)`. Its `toString()` redacts. Sleeper passes `None`, and its
  behaviour does not change.
- **`LeagueSnapshot.RosterEntry`** gains `defenseTeam` (an abbreviation, null otherwise). Today
  "team defense" is a regex on Sleeper's `"CLE"` ids; ESPN's are negative numbers.
- **`LeagueRepository.resolveSleeperIds`** becomes `resolveIds(platform, ids)`:
  - override first, then `external_ids->>platform`, refusing an id that two players hold;
  - `platform` comes from a two-value whitelist, never input;
  - ESPN reads use V10's `players_espn_id` index, which S0 measured at 496/496.
- **`LeagueLimits`** gets an `espnCall()` bucket: shared, sized from owner input 3, failing
  closed like Sleeper's.
- **`LeagueHttp.get(uri, headers)`**:
  - the cookie header is built in one place;
  - it already logs only a host and a status, and a log-capture test makes that a guarantee;
  - the ESPN host is already on the allowlist.
- **Connections:** public ESPN leagues share one connection per member with
  `external_user_id = "public"`. A private league's connection is keyed by its SWID. V11 already
  holds the credential columns and their CHECKs; **no migration is needed** unless the capture
  disproves an assumption.

### S4a — public leagues (no secrets anywhere; a PR on its own)
- **`EspnLeagueProvider`:**
  - accepts a full league URL or a bare id: parse `leagueId` only, digits only,
    ≤ 2,147,483,647;
  - one call with `view=mSettings&view=mTeam&view=mRoster&view=mMatchup&view=mStatus`;
  - maps 404 to "No ESPN league with that id this season" and 401 to "This league is private"
    (the S4b flow), with 400 refused before the call.
- **`EspnScoringMapper` → `LeagueScoring`:**
  - exact stat ids (3, 4, 19, 20, 24, 25, 26, 42, 43, 44, 53, 72, 101/102) go to `base`;
  - "every N yards" (5–10, 27–32, 47–52) becomes rate = points ÷ N, **reported as approximate**;
  - ranges 17/18, 37/38 and 56/57 become cumulative thresholds `Bonus(300, X)` and
    `Bonus(400, Y − X)`, only when |Y − X| ≤ 20; otherwise they are reported;
  - `pointsOverrides` for slots 0/2/4/6 become position overrides;
  - K, D/ST and IDP items go to unmodelled;
  - invalid scoring is refused, never clamped (S1's rule).
- **Slots:**
  - 0 QB, 2 RB, 4 WR, 6 TE;
  - 23 → FLEX_RWT, 3 → FLEX_WR, 5 → FLEX_WT, 7 (OP) → SUPERFLEX;
  - 16 → DST, 17 → K, 20 → BENCH, 21 → IR;
  - anything else is reported as unmodelled.
- **Schedule:** `schedule[]`, home and away team ids by `matchupPeriodId`, regular season only
  (`matchupPeriodCount`), each period mapped to its weeks through `matchupPeriods`. ESPN
  publishes the whole schedule, unlike Sleeper.
- **Teams and standings:** `record.overall` wins, losses and ties. Points are never read.
- **API:**
  - `POST /api/v1/leagues/espn/preview {league, season}` returns the name and teams, and
    **stores nothing**;
  - `POST /api/v1/leagues {platform: "espn", externalLeagueId, season, myTeamExternalId}`;
  - a public league has no account to check membership against, so the member picks their team.
- **Frontend:** the Connect panel offers Sleeper or ESPN. ESPN takes a league link or id and a
  season, previews, then "Which team is yours?" and Import. A 401 opens the private-league panel
  (S4b), or until then says plainly "This league is private; ask your commissioner to make it
  viewable to the public, or wait for private-league support".

### S4b — private leagues, opt-in "Keep this league synced"
- **`CredentialCipher`:**
  - JDK AES-256-GCM, a random 12-byte nonce per encryption;
  - associated data `"league_connection:" + id + ":user:" + userId`;
  - `key_version` recorded;
  - the key comes from `LEAGUE_CREDENTIAL_KEY` (in `.env.example` with no value);
  - **startup refuses** if encrypted rows exist and the key is missing;
  - with no key and no rows the app starts, and opting in is disabled with a stated reason.
- **Cookies travel only in a POST body.** They are never in a URL, never logged, never returned.
- **Use-once (the default):** import and every later sync take the cookies in the request body,
  use them in memory and drop them. A sync without cookies on such a league is a 409
  "Paste your ESPN cookies to sync".
- **Opt-in:** the cookies are encrypted onto the connection, and syncs decrypt per request. A 401
  marks the connection `ERROR` ("Your ESPN sign-in expired; paste new cookies"), with no retry
  loop.
- **The member's team** is found by SWID in `teams[].owners`.
- **"Stop keeping synced"** nulls the ciphertext immediately. Deleting the last league deletes
  the connection, as S1 does. Account deletion cascades.
- **UI:** what the two cookies are (a sign-in to the whole ESPN account), how to find them, how to
  revoke them (sign out of ESPN), and the alternative of asking the commissioner to make the
  league public. "Keep synced" is unchecked by default.
- **Threat note for the PR:** the key lives on the same VM as the database. That protects a
  leaked dump or backup, not a compromised VM.

## Tests
- **Mapper:**
  - against the captured `leaguedefaults` (real, public, 46 items);
  - step-scoring and range-bonus variants;
  - the |Y − X| > 20 refusal;
  - unmodelled keys reported, never dropped.
- **Provider:**
  - on fixtures: URL and id parsing, the 400/401/404 mapping (and nothing over 32 bits ever
    requested), slots, schedule periods, D/ST ids;
  - the redacted real-league capture once owner input 1 arrives.
- **Cipher:**
  - round trip;
  - a tampered ciphertext fails;
  - a ciphertext moved to another row or member fails, through the associated data;
  - the wrong key version fails;
  - startup refuses with rows and no key.
- **No leaks:** a log-capture test runs import, sync and failure paths with a known cookie value,
  and asserts it appears in no log line, exception message, problem detail or response body.
- **API:**
  - another member gets a 404 on every route;
  - preview writes nothing;
  - injection on every new parameter;
  - the use-once sync is a 409 without cookies;
  - "stop syncing" removes the ciphertext.
- **Mutations:** the S1 pattern, one per protected line: the redaction, the associated data, the
  401 mapping, the 32-bit check, the override-first resolution.

## Verification
- `./mvnw -B clean verify`; lint, tsc, tests and build for the frontend; `session-check` with
  0 FAIL and 0 drift.
- **Browser QA on localhost:**
  - public-league preview and import with the owner's league id, live;
  - the private path is exercised only with cookies the owner types themselves;
  - a deliberately expired or garbled cookie shows the reconnect message.
- **Timing:** an import is one ESPN call. Measure and report it.
- **Docs:** north-star row 7 status, `map.md`, `.env.example`, `deploy/README.md` (the key, and
  its backup), the plan doc's S4 status, and a review in the S1 format.

## Order and size

- Then **S4b** (private), which carries every credential concern, so it gets a review of its own.
