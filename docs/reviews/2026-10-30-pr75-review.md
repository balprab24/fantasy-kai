## Findings

1. **Fixed — an override could never correct a wrong match** (`ingest/PlayerMatcher.java`).
   Overrides were consulted after every heuristic, so they only filled gaps. Scenario: Sleeper
   lists a namesake who resolves uniquely by name + position to the wrong internal player; adding
   an override changed nothing, because the name rule returned first. The override is now checked
   first, and one naming a player who no longer exists still falls through.
   `overrideCorrectsWhatAHeuristicWouldGetWrong` fails on the old order. The plan's rule list was
   wrong in the same way and is corrected.
2. **Fixed — lost licence note.** The crosswalk's class doc again records Sleeper's non-commercial
   terms and the once-a-day player-map guidance.

The servers ran from this worktree: the API with ingest, backfill and projection jobs disabled,
and `next dev`. A throwaway `@example.test` account was registered through `/register` on
localhost and deleted afterwards, along with its 6 refresh tokens.

- **Board:**
  - `/rankings` loads 496 players;

  - the player overlay (Smith-Njigba, 7 GETs) renders its game log and chart.
  - `/profiles` renders. No console errors.
- **Member limiter:**
  - 125 reads with one token returned exactly 120 × 200, then 429 with `Retry-After: 60`;
    liveness stayed 200.
  - In the browser while throttled, the member stays signed in (refresh 200), and the board shows

- **Heap cost of the full Sleeper snapshot**, measured by parsing the captured 14.66 MB file with

  Production gives the JVM ~700 MB.

## What I did not fix, and why

- **Two Sleeper records resolving to one player are both dropped**, even when one matched on gsis
  and the other only on name. That costs coverage, not correctness, and measured coverage is 496/496.
  The fix needs the matcher to report which rule matched.
- **A wrong Sleeper id already stored on a player is never overwritten** (the `ATTACH` guard).
  An override now makes the matcher pick the right player, but the stale id stays on the wrong
  one, so two rows can carry the same id. Today it needs a manual clear. S1 must resolve league
  rosters through the matcher, not a raw `external_ids->>'sleeper'` lookup, or it must refuse
  duplicates.
- **120 reads/min against ~7 GETs per player overlay.** A member paging fast through players
  with previous/next can be throttled after about 17 players in a minute. The UI degrades well, so
  this is the owner's call on the number, not a bug.
- **The 429 headline reads "The board could not be scored"**, though the body is correct. It is
  frontend copy on main, so out of this PR's scope.
- **Phone width not re-checked.** This PR changes no frontend source compared with main, and the
  Chrome window refused to resize.
- **Style:** the import order and brace-less `if`s in `PlayerMatcher` and `SleeperCrosswalk`
  differ from the surrounding code. They were left as they are to keep this diff to behaviour.
- **The seeded overrides live in Java**, run on every ingest and are idempotent. A migration
  cannot hold them, because player ids differ between databases.

## The argument against merging as written

It is a 10k-line PR whose title says S0. Most of it is an earlier branch's backend, carried
across by patch onto a redesigned frontend that does not call half of the new endpoints
(board, performance, projections). That is API surface shipped without a UI, and it is
reviewed here only by reference to a previous pass on a different frontend. It would be wrong
if the patch had silently diverged from `7665721`; `git diff 7665721 HEAD -- backend/src`
showing only the S0 files is the evidence that it did not.
